# Lumenfall 1.0 — design

Date: 2026-10-22
Status: approved in conversation, awaiting written-spec review

## Intent

Lumenfall is an Android live-wallpaper host for Lively-style wallpaper bundles
(Kotlin platform shell, Rust core over JNI). Version 1.0.0 is its first public
release, for open-source enthusiasts, distributed through **GitHub Releases**
(sideload / Obtainium) and **F-Droid**.

Success means:

- every item in `docs/CODE-REVIEW-2026-07-04.md` (31 items) is resolved;
- the full test gate passes (Rust tests, Kotlin unit tests, lint with zero
  errors and warnings-as-errors, shim check, vendored-wallpaper lock check,
  release assemble, reproducible-build check);
- the scripted smoke run passes on the user's own device and the user approves
  the screenshots;
- the repo is public, `v1.0.0` is released on GitHub with a signed APK, and an
  F-Droid recipe is ready for the user to submit.

Decisions made with the user:

| Topic | Decision |
|---|---|
| Channels | GitHub Releases + F-Droid. No Play Store. |
| Updates | No in-app update check; document Obtainium. |
| Review scope | Every item in the July review, including #13 and #19. |
| Application ID | `com.sdelavega.lumenfall` (package renamed too). |
| Version | `1.0.0`, `versionCode 10000`. |
| Rain (CC BY-NC-SA) | Replaced by an original wallpaper, "Rainfall". |
| WeatherAether location | No ipapi.co / BigDataCloud in Lumenfall: device location or typed city. |
| WeatherAether source | Slaved to ÆtherDesk via a pinned vendor sync (all four ÆtherDesk wallpapers). |
| Upstream fallbacks | Kept in ÆtherDesk behind a host opt-in capability flag. |
| Signing | Local, with the user's existing keystore; reproducible build so F-Droid ships the developer signature. |
| Device verification | User's own device over adb (no emulator). |
| Licence | GPL-3.0-or-later, "Copyright (C) 2026 Stephen de la Vega", donations via GitHub Sponsors. |

Out of scope: Play Store, App Bundles, x86_64 ABI, in-app updater, new
wallpaper types, an ÆtherDesk release.

## 1. Identity, licensing, reproducible build

### Identity

- `applicationId` and `namespace` become `com.sdelavega.lumenfall`; Kotlin
  sources move from `com/aetherdesk/lumenfall` to `com/sdelavega/lumenfall`.
- Rust JNI exports are renamed to match (`Java_com_sdelavega_lumenfall_core_LumenfallCore_*`).
  A JVM test asserts the `external fun` names in `LumenfallCore.kt` and a Rust
  test asserts the exported symbol names, so the two cannot drift.
- `proguard-rules.pro` keep rules follow the rename.
- The **bundle-facing bridge contract does not change**: `window.aetherDesk.*`,
  the shim API, and Lively compatibility hooks keep their names so bundles
  written for ÆtherDesk run unchanged.
- `versionName = "1.0.0"`, `versionCode = 10000` (derived `major*10000 + minor*100 + patch`).
  `scripts/bundle-version.sh X.Y.Z` stamps `app/build.gradle.kts` and
  `core-rust/Cargo.toml` and refuses inconsistent input.
- The keystore (`release.jks`, `keystore.properties`) stays git-ignored and is
  never read, printed, moved or modified by tooling or agents.

### Licensing

- Top-level `LICENSE` (GPL-3.0 full text).
- Source headers: `// Copyright (C) 2026 Stephen de la Vega` +
  `// SPDX-License-Identifier: GPL-3.0-or-later` on Kotlin, Rust, Gradle and
  scripts we own (not on vendored wallpapers). A gate check enforces presence.
- `THIRD_PARTY.md`: each bundled wallpaper (author, licence, source URL) and
  each library dependency family (AndroidX, Material, Media3, Rust crates).
- An "Open-source licences" screen reachable from About lists the same, read
  from a generated asset; per-bundle licence files continue to ship inside
  their bundle folders.
- `.github/FUNDING.yml` → `github: sdelavega`; About pane gets a Donate link.

### Reproducible build

- `rust-toolchain.toml` pins an exact stable Rust with the
  `aarch64-linux-android` target; NDK `27.3.13750724`, AGP, Kotlin and the
  Gradle wrapper stay pinned; JDK 17 documented.
- Cargo release profile: `codegen-units = 1`, `lto = true`, `strip = true`,
  `panic = "abort"`; builds use `--locked`; `RUSTFLAGS` adds
  `--remap-path-prefix` for the workspace, `$CARGO_HOME` and the rustup home so
  no build-machine path reaches the `.so`.
- The `cargoNdkBuild` task no longer hard-codes `~/.cargo/bin`: it uses `cargo`
  from `PATH`, overridable by a `CARGO` environment variable.
- `android { dependenciesInfo { includeInApk = false; includeInBundle = false } }`;
  no build timestamps or VCS info in the APK.
- `just repro-check` performs two clean release builds in separate temporary
  copies of the tree and compares the unsigned APKs (and the `.so`) byte for
  byte, printing the first differing entry on failure.
- **Fallback:** if byte-identical output cannot be reached within the plan, the
  F-Droid recipe drops `Binaries`/`AllowedAPKSigningKeys` (F-Droid signs with
  its own key) and `README.md` documents that GitHub and F-Droid installs are
  not interchangeable. This fallback is chosen by the coordinator and recorded
  in the ledger, not silently.

## 2. Code-review resolution

All 31 items in `docs/CODE-REVIEW-2026-07-04.md`. That file is committed on
the release branch and each item annotated with its resolution and commit.

### A. Threading and lifecycle

- **#4** `PerformanceSettingsBus`, `PropertyBus`, `ActiveBundleBus` (and new
  `BundleDeletedBus`) deliver listeners on the main thread via a shared
  `MainThreadDispatcher` (posts when called off-main, runs inline on main).
  Unit-tested with an injectable dispatcher.
- **#10** `WallpaperWebViewHost` mutates `failed`, `virtualDisplay`,
  `presentation` only on the main thread; callbacks from WebView-internal
  threads hop through `mainHandler.post`.
- **#12** Deep-sleep snapshot bitmap is allocated inside the PixelCopy flow and
  recycled in `finally` on every failure path.
- **#17** Deep sleep is scheduled only after an actual `setVisible(false)`, not
  at engine creation.
- **#5** Shim tracks `suspended` and sends no watchdog tick while suspended;
  the host additionally ignores ticks received while the engine is hidden.
- **#3** `BundleThumbnailer` uses a single-threaded serial queue of pending
  bundle ids (deduplicated); no `running` flag, no recursion.

### B. Storage and import

- **#9, #18** `BundleStore` caches the parsed property schema per bundle id;
  invalidated on import, delete and bundled-asset upgrade.
- **#8** All override JSON reads are fault-tolerant (bundled and imported
  branches alike); corrupt data yields empty overrides and a log line.
- **#30** Pref keys use a collision-proof encoding; existing keys migrate once
  on first launch (versioned migration marker).
- **#23** Property parsing returns a result type carrying the Rust error
  message; Settings shows "Couldn't read this wallpaper's settings: <reason>"
  instead of "no configurable properties".
- **#6, #24** `BundleDeletedBus` notifies on delete; `BundleSettingsActivity`
  tears down its preview and finishes when its bundle is deleted, and also
  checks `store.get(id) == null` in `onResume`.
- **#2** The importer logs every script file it skips; if any file is skipped,
  a screening result of *allowed* is downgraded to *limited* with a reason.
- **#22** Comment in `BundleFiles.findLivelyInfo` explaining the shallowest-match
  tiebreak.
- **#15** `BundleImporterTest` (JVM) against a fake of the Rust-core facade
  (introduce a narrow `CoreApi` interface the importer depends on):
  zip-slip throws and cleans the directory; invalid `LivelyInfo` throws and
  cleans; screening rejection cleans; valid bundle writes meta and
  `screening.json`.

### C. Network and privacy

- **#7** `WebSocketGuard` validation runs on a bounded executor (max 8 in
  flight; excess rejected with a clear error) with a short-TTL DNS cache.
- **#16** Reverse geocoding is skipped when `Geocoder.isPresent()` is false
  and otherwise uses the asynchronous `getFromLocation(..., listener)` API.
- **#19** The tracker/ad and always-blocked host lists move into `core-rust`
  (one module, one source) and are exposed over JNI; the Rust screener and
  `WallpaperNetworkPolicy`/`WebSocketGuard` consume the same list. Rust tests
  assert canonical entries (`googletagmanager.com`, `doubleclick.net`, …) and
  a Kotlin test asserts the policy blocks them via the JNI-loaded list (fake in
  JVM tests).
- **#28** Dead `metadata.azure.com` entries removed (raw IPs remain covered).
- Lumenfall additionally blocks `ipapi.co` and `api.bigdatacloud.net` for all
  bundles (see §3).

### D. UI

- **#1** "Now live" is shown only after the live-wallpaper chooser returns and
  `WallpaperManager` reports our component active; the already-active branch
  says "Switched to <title>" after the in-place swap succeeds.
- **#11, #20** `MainActivity` list becomes a `RecyclerView` + `ListAdapter` with
  `DiffUtil`; thumbnail completion updates one row.
- **#21** `SplitPaneLayout` divider calls `performClick()` and exposes
  accessibility actions to widen/narrow the pane.
- **#29** Activation failures show a dialog with the reason and a Re-import hint.
- **#27** `assets/spike/` removed; a "Pick a wallpaper to begin" placeholder
  page renders when no bundle is active.
- **#13** `PropertySchema` sealed hierarchy — `Slider(min,max,step)`, `Color`,
  `Checkbox`, `Dropdown(items)`, `FolderDropdown(folder, filter, extensions)`,
  `Text`, `Button`, `Label` — parsed once from the Rust envelope with unit
  tests per kind; `raw` JSON is private to the parser and no UI code performs
  string-keyed lookups.

### E. Bridge shim and dead code

- **#14** The shim moves to `app/src/main/assets/bridge/aetherdesk-shim.js`,
  read once and cached; per-bundle values are injected as a small generated
  prefix. The gate runs `node --check` on it when `node` is available, and a
  JVM test always checks it loads and contains the required entry points.
  The shim treats unknown host-only calls (e.g. `reportWeatherRendererStatus`)
  as harmless no-ops.
- **#26** `web/WebWallpaperRenderer.kt` deleted.
- **#25** On the user's device, check whether the WebView renderer's
  `/proc/<pid>/stat` is readable. If readable, the governor includes it. If
  not (expected on Android 13+ isolated processes), the governor's CPU signal
  is supplemented with frame-time pressure reported by the shim, and the
  limitation is documented in `ARCHITECTURE.md`.

### Lint

- Fix the `CoarseFineLocation` error by declaring `ACCESS_COARSE_LOCATION`
  alongside `ACCESS_FINE_LOCATION` and requesting both, so the user can grant
  approximate location (which the geolocation bridge must handle).
- Triage all warnings: fix, or suppress with a written reason in `lint.xml`.
  Lint runs with `warningsAsErrors = true` and `abortOnError = true`.

## 3. Bundled wallpapers

### Rainfall (new, replaces Rain)

- Folder `app/src/main/assets/wallpapers/Rainfall/`, original work,
  GPL-3.0-or-later, written from scratch (no code from rocksdanister/rain).
- WebGL rain-on-glass drops over a background, Canvas 2D fallback when WebGL
  is unavailable.
- Properties: intensity, speed, drop size, blur, tint colour, lightning toggle,
  background image chosen from the bundle's own `backgrounds/` folder
  (FolderDropdown).
- 2–3 backgrounds generated procedurally as original art (no third-party
  images).
- Uses the bridge contract: FPS cap, suspend/resume, `onPropertyChange`,
  `livelyPropertyListener`.
- Screens as *allowed* or *limited*; has a thumbnail.
- `LivelyRain` is removed from assets and `BundledWallpapers`. A one-time
  migration moves an active `bundled/LivelyRain` to `bundled/Rainfall` and
  drops its overrides.

### ÆtherDesk wallpapers: pinned vendor sync

- Vendored set: `WeatherAether`, `GradientWave`, `MatrixRain`, `NeonCity`.
- `just sync-wallpapers <aetherdesk-ref>` (script `scripts/sync-aetherdesk-wallpapers.sh`)
  exports `Resources/Wallpapers/<name>` from a local ÆtherDesk checkout at
  exactly that commit with `git archive` (committed files only), replaces the
  vendored folders, and writes `app/src/main/assets/wallpapers/wallpapers.lock`
  containing the upstream repo URL, full commit hash, and a SHA-256 per file.
  The ÆtherDesk checkout path comes from `AETHERDESK_DIR` (no hard-coded path).
- A JVM unit test re-hashes the vendored files against `wallpapers.lock` and
  fails on any hand edit, missing or extra file.
- Each vendored folder's metadata fixes (e.g. `License` fields) are made
  upstream, never locally.

### Upstream ÆtherDesk change

- WeatherAether runs its ipapi.co (IP geolocation) and BigDataCloud (reverse
  geocoding) code paths only when
  `window.aetherDesk.system.capabilities.ipGeolocation === true`. ÆtherDesk's
  macOS host sets this flag, so ÆtherDesk's behaviour is unchanged.
- With the flag absent: auto mode uses `navigator.geolocation` only; on denial
  or failure it uses the cached location, else shows a "Set a city in this
  wallpaper's settings" notice; place labels come from Open-Meteo geocoding
  (manual mode) or rounded coordinates / "Current location".
- Coordination: ÆtherDesk v1.4 (separate session) is rewriting WeatherAether.
  The flag lands either as part of that work or on a branch after its
  WeatherAether tasks merge — never with two sessions editing WeatherAether at
  once. Lumenfall's WeatherAether sync task is gated on that ÆtherDesk commit;
  if v1.4 slips, pin a `main` commit containing only the flag change.
- Lumenfall never sets the flag, and its network policy blocks both hosts as
  defence in depth.

### Other bundled wallpapers

Fluids (MIT), The Hill (MIT), Triangles & Light (MIT) stay, with `License`
fields matching their licence files.

## 4. Release pipeline, CI, docs, verification

### justfile

- `just gate`: `no-home-paths` (tracked files, built `.so`, APK) → `header` →
  `rust-test` → `deny` (cargo-deny licences + advisories) → `kotlin-test` →
  `lint` → `shim-check` → `wallpapers-lock` → `assemble-release` →
  `repro-check`.
- `just release X.Y.Z [--publish]`:
  - preflight: clean `main` equal to `origin/main`; version equals Gradle,
    Cargo and the existence of `docs/releases/X.Y.Z.md`;
  - runs `just gate`;
  - builds and signs with the existing local signing configuration (never
    reading or echoing secrets);
  - `apksigner verify --print-certs` and compares the certificate SHA-256 with
    `docs/signing-cert.sha256` (committed fingerprint, public information);
  - writes `dist/Lumenfall-X.Y.Z.apk` and `.sha256`;
  - `--publish` shows tag, checksum and notes, requires typing the exact
    version, then tags `vX.Y.Z`, pushes the tag and runs
    `gh release create` with APK, checksum and notes. No `--yes`.
- `just sync-wallpapers <ref>`, `just repro-check`, `just smoke` (device).

### CI (GitHub Actions)

- `ci.yml` on push to `main` and PRs, `ubuntu-latest`: pinned Rust via
  `rust-toolchain.toml`, NDK via `sdkmanager`, JDK 17; runs the gate minus
  signing. Actions pinned by commit SHA.
- `dependabot.yml` for Gradle, Cargo, GitHub Actions.
- No release or signing workflow.

### F-Droid preparation

- `fastlane/metadata/android/en-US/`: `title.txt`, `short_description.txt`,
  `full_description.txt` (incl. contacted services and any anti-features),
  `changelogs/10000.txt`, `images/icon.png`, phone and tablet screenshots taken
  on the user's device.
- `docs/fdroid/com.sdelavega.lumenfall.yml`: draft `fdroiddata` recipe — rustup
  toolchain + target install, NDK pin, `gradle: [yes]`, `Binaries:` URL
  template for the GitHub release APK, `AllowedAPKSigningKeys:` fingerprint,
  `AutoUpdateMode: Version`, `UpdateCheckMode: Tags`, declared anti-features.
- If `fdroidserver` installs without sudo (pipx), run `fdroid lint` and a
  local build dry run; otherwise review the recipe manually.
- The user submits the fdroiddata merge request from their own GitLab account.

### Docs

New or rewritten: `README.md` (what, screenshots, install via GitHub /
Obtainium / F-Droid, bundle compatibility, privacy, build, donate),
`docs/releasing.md`, `SECURITY.md`, `CONTRIBUTING.md`, `THIRD_PARTY.md`,
`docs/releases/1.0.0.md`; `docs/ARCHITECTURE.md` updated (rename, typed schema,
shim asset, vendor sync, governor signal, blocklist in Rust).

### Device verification (`just smoke`)

Scripted over adb against the user's device:

1. install the release APK; set Lumenfall as the live wallpaper (user taps the
   system confirmation);
2. cycle all 8 bundled wallpapers, screenshot each, and scan `logcat` for
   crashes, ANRs and watchdog errors;
3. import a test Lively zip; change a property live in Settings;
4. delete the active bundle with its Settings open (#6/#24);
5. rotate;
6. 30-minute hidden/visible soak with logcat scan;
7. #25 `/proc` readability probe.

The user reviews the screenshots and approves before any tag.

### Publishing (each step needs the user's go-ahead)

1. Create `sdelavega/lumenfall` on GitHub as **private**, push `main`, CI green.
2. Make the repository public.
3. `just release 1.0.0 --publish` (tag + GitHub release).
4. User submits the F-Droid merge request.

No Homebrew tap (Android app).

## Working method

- Branch `release/1.0` in worktree `~/src/Lumenfall-1.0`; merged to `main`
  after the final review.
- Implementer: one fresh Claude Sonnet subagent per task.
- Reviewer: GLM-5.3 via `opencode run -m openrouter/z-ai/glm-5.3`, one review
  per task, diff supplied as a file, tests run in the foreground.
- Coordinator (Claude Opus): briefs, conflict rulings in the git-ignored
  `.superpowers/ledger.md`, final whole-branch review.
- Standing constraints: no sudo; no privacy/system-setting changes; never
  print the environment, commit secrets or home paths; never touch the
  keystore or other credentials; no writes to `/Volumes/*`; every outward step
  (push, public, tag, release) waits for the user.
